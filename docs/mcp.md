# ServerHoster MCP

ServerHoster exposes an [MCP (Model Context Protocol)](https://modelcontextprotocol.io) interface to allow AI agents and language models to securely interact with your server, manage services, and debug issues.

There are two primary ways to connect to the ServerHoster MCP interface:

## Global Control Plane (For External Agents like Grok or Claude)

The **Global Control Plane MCP** is a single endpoint that exposes tools to manage the entire host, all projects, and all services. This is ideal when you want to connect a persistent external AI bot (e.g. Grok Bot, Claude Desktop, or a custom Slack bot) directly to your server.

**Endpoint:** POST /mcp  
**Authentication:** Requires a Bearer token. Use the **durable API token** from **Settings → Dev Tools → API / MCP Token**.

### Getting Your API Token

ServerHoster provides a durable API/MCP token that persists across restarts and redeploys:

1. Navigate to **Settings** in the dashboard
2. Go to the **Dev Tools** tab
3. Find the **API / MCP Token** card
4. Click **Reveal** to view the full token
5. Click **Copy Token** to copy it to your clipboard

The token is permanent until you explicitly rotate it. If you need to invalidate an old token, click **Rotate** to generate a new one.

**Token Format:**
```
Authorization: Bearer <your-40-character-token>
```

**Legacy Bootstrap:** On first start (or if no persisted token exists), ServerHoster seeds the durable token from `SURVHUB_AUTH_TOKEN` if set. After that, the persisted token is the source of truth and survives redeploys even if the environment variable changes.

### Connecting via mcp-remote (Grok Bot, Claude Desktop)

Recommended client wrapper:

```json
{
  "mcpServers": {
    "serverhoster": {
      "command": "npx",
      "args": [
        "-y",
        "mcp-remote",
        "http://YOUR_HOST:8787/mcp",
        "--allow-http",
        "--header",
        "Authorization: Bearer YOUR_TOKEN_FROM_SETTINGS"
      ]
    }
  }
}
```

Use the token from **Settings → Dev Tools → API / MCP Token** (not a dashboard session cookie). Wrong or missing Bearer returns **401 immediately** with JSON-RPC error `-32000` (not a hang).

### Timeouts and reliability

- Prefer a **client request timeout of at least 30–60 seconds**. Read tools (`list_services`, `get_service_logs`, `get_system_health`) normally complete in well under that; ServerHoster bounds Docker/disk probes so a stuck daemon returns a clear error instead of hanging past ~30s.
- `MCP error -32001: Request timed out` on the client usually means the **client** gave up waiting. Check that the durable token matches Settings, that `GET /health` is 200, and that the host can reach Docker when calling health/database tools.
- ServerHoster serves Streamable HTTP with **JSON responses** on `POST /mcp` (stateless). Clients must send `Accept: application/json, text/event-stream`.

### Available Global Tools

- get_system_health: Get host health, Docker status, CPU, memory, and disk usage.
- list_projects: List all projects.
- list_services: List all services and their runtime status.
- get_service_status: Get detailed status, environment requirements, and latest deploy state for a specific service.
- get_service_logs: Fetch recent container stdout/stderr logs for a service.
- search_service_logs: Search logs for a case-insensitive query string.
- start_service / stop_service / restart_service: Manage service lifecycle.
- redeploy_service: Trigger a fresh git pull and rebuild/redeploy for a service (may take longer than other tools; raise the client timeout for deploys).
- list_databases: List all managed databases and their status.
- get_database_logs: Fetch recent container logs for a managed database.

### Host Memory Alerts

In addition to the pull-based `get_system_health` tool, ServerHoster supports **push-based host memory alerts**. When configured, ServerHoster automatically POSTs a webhook when memory usage crosses a threshold, eliminating the need for external polling cron jobs.

See `docs/operations.md` for setup instructions.

## Ephemeral Service-Scoped Agents (Internal Terminal)

ServerHoster also provides a built-in terminal AI companion. When you open an AI chat for a specific service in the ServerHoster dashboard, it provisions a **short-lived, service-scoped MCP session**.

**Endpoint:** POST /mcp/:tokenId  
**Authentication:** Handled automatically via temporary tokens generated by the dashboard.

This interface restricts tools specifically to the selected service (e.g., executing commands inside its container, reading its environment, marking its logs) to maintain the principle of least privilege.
